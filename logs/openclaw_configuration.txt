### config.apply (Full Configuration Replacement)

Source: https://github.com/openclaw/openclaw/blob/main/docs/gateway/configuration.md

Applies a full configuration replacement to the Openclaw gateway. This RPC validates and writes the entire configuration, followed by a gateway restart. It supports options for providing the configuration as a JSON5 string, specifying a base hash for optimistic concurrency control, and configuring restart behavior.

```APIDOC

### Method
POST

### Endpoint
/config.apply

### Parameters

- **baseHash** (string) - Optional - Config hash from `config.get` (required when config exists).
- **sessionKey** (string) - Optional - Session key for the post-restart wake-up ping.
- **note** (string) - Optional - Note for the restart sentinel.

### Hooks Configuration

Source: https://github.com/openclaw/openclaw/blob/main/docs/gateway/configuration-reference.md

Configure the Hooks system for integrating external services and automating workflows.

```APIDOC
## Hooks Configuration

### Description
Configure the Openclaw Hooks system for integrating external services and automating workflows.

### Method
N/A (Configuration)

### Endpoint
N/A (Configuration)

### Parameters
#### Hooks Configuration Object
- **enabled** (boolean) - Enables the hooks system. Default `true`.
- **token** (string) - Shared secret for authentication.
- **path** (string) - The base path for hook endpoints. Default `/hooks`.
- **maxBodyBytes** (integer) - Maximum allowed request body size in bytes. Default `262144`.
- **defaultSessionKey** (string) - Default session key for hook agent runs. Default `hook:ingress`.
- **allowRequestSessionKey** (boolean) - Allows callers of `/hooks/agent` to set `sessionKey`. Default `false`.
- **allowedSessionKeyPrefixes** (string array) - Optional prefix allowlist for explicit `sessionKey` values. Example: `["hook:"]`.
- **allowedAgentIds** (string array) - Restricts explicit agent routing. `*` or omitted allows all, `[]` denies all.
- **presets** (string array) - Predefined hook presets. Example: `["gmail"]`.
- **transformsDir** (string) - Directory for custom transform modules. Example: `~/.openclaw/hooks/transforms`.
- **mappings** (array) - Array of hook mapping configurations.
  - **match** (object) - Matching criteria for a hook.
    - **path** (string) - Matches sub-path after `/hooks` (e.g., `gmail` for `/hooks/gmail`).
    - **source** (string) - Matches a payload field for generic paths.
  - **action** (string) - The action to perform (e.g., `agent`).
  - **agentId** (string) - Routes to a specific agent.
  - **wakeMode** (string) - How to wake the agent (`now` or `next-heartbeat`).
  - **name** (string) - Name of the hook mapping.
  - **sessionKey** (string) - Session key template for the hook agent run.
  - **messageTemplate** (string) - Template for the message sent to the agent.
  - **deliver** (boolean) - Whether to send the final reply to a channel.
  - **channel** (string) - The channel to send the reply to. Defaults to `last`.
  - **model** (string) - Overrides the LLM model for this hook run.
  - **transform** (object) - Configuration for custom transform modules.
    - **module** (string) - Relative path to the transform module within `transformsDir`.

### Authentication
- **Authorization: Bearer `<token>`**
- **x-openclaw-token: `<token>`**

### Request Example
```json
{
  "hooks": {
    "enabled": true,
    "token": "shared-secret",
    "path": "/hooks",
    "maxBodyBytes": 262144,
    "defaultSessionKey": "hook:ingress",
    "allowRequestSessionKey": false,
    "allowedSessionKeyPrefixes": ["hook:"],
    "allowedAgentIds": ["hooks", "main"],
    "presets": ["gmail"],
    "transformsDir": "~/.openclaw/hooks/transforms",
    "mappings": [
      {
        "match": { "path": "gmail" },
        "action": "agent",
        "agentId": "hooks",
        "wakeMode": "now",
        "name": "Gmail",
        "sessionKey": "hook:gmail:{{messages[0].id}}",
        "messageTemplate": "From: {{messages[0].from}}\nSubject: {{messages[0].subject}}\n{{messages[0].snippet}}",
        "deliver": true,
        "channel": "last",
        "model": "openai/gpt-5.2-mini"
      }
    ]
  }
}
```

### Response
#### Success Response (200)
Configuration is applied. No specific response body for configuration changes.

#### Response Example
N/A
```

### Gateway Configuration (JSON5)

Source: https://github.com/openclaw/openclaw/blob/main/docs/gateway/configuration-reference.md

This JSON5 snippet defines the configuration for the Openclaw Gateway. It includes settings for mode, port, binding, authentication, Tailscale integration, Control UI, and remote connections. Authentication options range from none to token, password, and trusted-proxy, with configurable rate limiting.

```json5
{
  "gateway": {
    "mode": "local", // local | remote
    "port": 18789,
    "bind": "loopback",
    "auth": {
      "mode": "token", // none | token | password | trusted-proxy
      "token": "your-token",
      // password: "your-password", // or OPENCLAW_GATEWAY_PASSWORD
      // trustedProxy: { userHeader: "x-forwarded-user" }, // for mode=trusted-proxy; see /gateway/trusted-proxy-auth
      "allowTailscale": true,
      "rateLimit": {
        "maxAttempts": 10,
        "windowMs": 60000,
        "lockoutMs": 300000,
        "exemptLoopback": true,
      },
    },
    "tailscale": {
      "mode": "off", // off | serve | funnel
      "resetOnExit": false,
    },
    "controlUi": {
      "enabled": true,
      "basePath": "/openclaw",
      // root: "dist/control-ui",
      // allowedOrigins: ["https://control.example.com"], // required for non-loopback Control UI
      // dangerouslyAllowHostHeaderOriginFallback: false, // dangerous Host-header origin fallback mode
      // allowInsecureAuth: false,
      // dangerouslyDisableDeviceAuth: false,
    },
    "remote": {
      "url": "ws://gateway.tailnet:18789",
      "transport": "ssh", // ssh | direct
      "token": "your-token",
      // password: "your-password",
    },
    "trustedProxies": ["10.0.0.1"],
    // Optional. Default false.
    "allowRealIpFallback": false,
    "tools": {
      // Additional /tools/invoke HTTP denies
      "deny": ["browser"],
      // Remove tools from the default HTTP deny list
      "allow": ["gateway"],
    },
  },
}

### Sandbox Session Visibility Configuration

Source: https://github.com/openclaw/openclaw/blob/main/docs/concepts/session-tool.md

Configure how session tools are scoped to control cross-session access, particularly within sandboxed environments.

```APIDOC
## Sandbox Session Visibility

### Description
Controls the visibility of session tools to limit cross-session access. This is particularly relevant for sandboxed sessions where stricter access controls may be required.

### Method
N/A (Configuration)

### Endpoint
N/A (Configuration)

### Parameters
#### Configuration Options
- `tools.sessions.visibility` (string: "self" | "tree" | "agent" | "all") - Optional - Defaults to "tree". Defines the scope of session visibility.
  - `self`: Only the current session key.
  - `tree`: Current session and sessions spawned by the current session.
  - `agent`: Any session belonging to the current agent ID.
  - `all`: Any session (cross-agent access still requires `tools.agentToAgent`).
- `agents.defaults.sandbox.sessionToolsVisibility` (string: "spawned" | "all") - Optional - Defaults to "spawned". For sandboxed sessions, this clamps visibility.
  - `spawned`: Clamps visibility to "tree" even if `tools.sessions.visibility` is set to "all".
  - `all`: Allows visibility as defined by `tools.sessions.visibility`.

### Request Example
```json5
{
  "tools": {
    "sessions": {
      "visibility": "tree" 
    }
  },
  "agents": {
    "defaults": {
      "sandbox": {
        "sessionToolsVisibility": "spawned" 
      }
    }
  }
}
```

### Response
#### Success Response (200)
N/A (Configuration)

#### Response Example
N/A (Configuration)
```

### Configuration Schema RPC Endpoints

Source: https://github.com/openclaw/openclaw/blob/main/docs/experiments/onboarding-config-protocol.md

These endpoints provide access to the configuration schema and allow for schema lookups within a specific path.

```APIDOC
## RPC Endpoints for Configuration Schema

### Description
Provides endpoints to retrieve the overall configuration schema and to perform lookups for specific configuration paths, including associated UI hints.

### Methods and Endpoints

#### `config.schema`

- **Method**: POST (Assumed)
- **Endpoint**: `/gateway/rpc` (Assumed)
- **Description**: Retrieves the complete configuration schema and associated UI hints.
- **Parameters**:
  - **Path Parameters**: None
  - **Query Parameters**: None
  - **Request Body**:
    - `{}` (empty object) - No specific parameters required.

### Request Example
```json
{
  "method": "config.schema",
  "params": {}
}
```

### Response Example (Success)
```json
{
  "schema": { ... },
  "uiHints": { ... },
  "version": "1.2.0",
  "generatedAt": "2023-10-27T10:00:00Z"
}
```

#### `config.schema.lookup`

- **Method**: POST (Assumed)
- **Endpoint**: `/gateway/rpc` (Assumed)
- **Description**: Retrieves the configuration schema and UI hint for a specific configuration path.
- **Parameters**:
  - **Path Parameters**: None
  - **Query Parameters**: None
  - **Request Body**:
    - `path` (string) - Required - The configuration path to look up (e.g., "project.name").

### Request Example
```json
{
  "method": "config.schema.lookup",
  "params": {
    "path": "project.dependencies"
  }
}
```

### Response Example (Success)
```json
{
  "path": "project.dependencies",
  "schema": { ... },
  "hint": { ... },
  "hintPath": "project.dependencies",
  "children": [
    { "path": "project.dependencies.0" },
    { "path": "project.dependencies.1" }
  ]
}
```

### General Config Schema Response Fields
- `schema` (object) - The JSON schema definition for the configuration or path.
- `uiHints` (object) - Keyed by path, contains optional metadata for rendering UI elements (label, help, group, order, advanced, sensitive, placeholder).
- `version` (string) - The version of the configuration schema.
- `generatedAt` (string) - The timestamp when the schema was generated.
- `path` (string) - The configuration path being looked up (for `lookup` endpoint).
- `hint` (object) - UI hint metadata for the specific path (for `lookup` endpoint).
- `hintPath` (string) - The path associated with the hint (for `lookup` endpoint).
- `children` (array) - An array of child paths for the given path (for `lookup` endpoint).
```
