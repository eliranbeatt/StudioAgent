### Configure fly.toml for OpenClaw Deployment

Source: https://github.com/openclaw/openclaw/blob/main/docs/install/fly.md

This TOML configuration file defines the settings for deploying OpenClaw on Fly.io. It specifies the app name, build settings, environment variables, process configuration, HTTP service settings, VM size, and volume mounts for persistent storage. Key settings include binding to LAN, allowing unconfigured startup, matching internal port, recommended memory, and persisting state to `/data`.

```toml
app = "my-openclaw"  # Your app name
primary_region = "iad"

[build]
  dockerfile = "Dockerfile"

[env]
  NODE_ENV = "production"
  OPENCLAW_PREFER_PNPM = "1"
  OPENCLAW_STATE_DIR = "/data"
  NODE_OPTIONS = "--max-old-space-size=1536"

[processes]
  app = "node dist/index.js gateway --allow-unconfigured --port 3000 --bind lan"

[http_service]
  internal_port = 3000
  force_https = true
  auto_stop_machines = false
  auto_start_machines = true
  min_machines_running = 1
  processes = ["app"]

[[vm]]
  size = "shared-cpu-2x"
  memory = "2048mb"

[mounts]
  source = "openclaw_data"
  destination = "/data"
```

### Render Blueprint Configuration (render.yaml)

### Setup and Onboarding

Source: https://github.com/openclaw/openclaw/blob/main/docs/cli/index.md

Commands and options for initializing the Openclaw configuration and workspace, including an interactive wizard.

```APIDOC
## Setup and Onboarding

### `setup` Command

Initializes configuration and workspace.

#### Options
- `--workspace <dir>`: Specifies the agent workspace path. Defaults to `~/.openclaw/workspace`.
- `--wizard`: Runs the interactive onboarding wizard.
- `--non-interactive`: Runs the wizard without prompts.
- `--mode <local|remote>`: Sets the wizard mode to local or remote.
- `--remote-url <url>`: Specifies the remote Gateway URL.
- `--remote-token <token>`: Provides a token for the remote Gateway.

**Note**: The wizard automatically runs if any wizard-related flags are present (e.g., `--non-interactive`, `--mode`, `--remote-url`, `--remote-token`).

### `onboard` Command

An interactive wizard to set up the gateway, workspace, and skills.

#### Options
- `--workspace <dir>`: Specifies the agent workspace path.
- `--reset`: Resets configuration, credentials, and sessions before starting the wizard.
- `--reset-scope <config|config+creds+sessions|full>`: Defines the scope of the reset. Defaults to `config+creds+sessions`. `full` also removes the workspace.
- `--non-interactive`: Runs the wizard without prompts.
- `--mode <local|remote>`: Sets the wizard mode to local or remote.
- `--flow <quickstart|advanced|manual>`: Specifies the onboarding flow. `manual` is an alias for `advanced`.
- `--auth-choice <setup-token|token|chutes|openai-codex|openai-api-key|openrouter-api-key|ai-gateway-api-key|moonshot-api-key|moonshot-api-key-cn|kimi-code-api-key|synthetic-api-key|venice-api-key|gemini-api-key|zai-api-key|mistral-api-key|apiKey|minimax-api|minimax-api-lightning|opencode-zen|custom-api-key|skip>`: Selects the authentication method.
- `--token-provider <id>`: (Non-interactive) Specifies the token provider ID when using `--auth-choice token`.
- `--token <token>`: (Non-interactive) Provides the token when using `--auth-choice token`.
- `--token-profile-id <id>`: (Non-interactive) Sets the token profile ID. Defaults to `<provider>:manual`.
- `--token-expires-in <duration>`: (Non-interactive) Sets the token expiration duration (e.g., `365d`, `12h`).
- `--secret-input-mode <plaintext|ref>`: Sets the mode for secret input. Defaults to `plaintext`. `ref` stores provider default environment references instead of plaintext keys.
- `--anthropic-api-key <key>`: Sets the Anthropic API key.
- `--openai-api-key <key>`: Sets the OpenAI API key.
- `--mistral-api-key <key>`: Sets the Mistral API key.
- `--openrouter-api-key <key>`: Sets the OpenRouter API key.
- `--ai-gateway-api-key <key>`: Sets the AI Gateway API key.
- `--moonshot-api-key <key>`: Sets the Moonshot API key.
- `--kimi-code-api-key <key>`: Sets the Kimi Code API key.
- `--gemini-api-key <key>`: Sets the Gemini API key.
- `--zai-api-key <key>`: Sets the Zai API key.
- `--minimax-api-key <key>`: Sets the Minimax API key.
- `--opencode-zen-api-key <key>`: Sets the OpenCodeZen API key.
- `--custom-base-url <url>`: (Non-interactive) Sets the base URL for custom API providers when using `--auth-choice custom-api-key`.
- `--custom-model-id <id>`: (Non-interactive) Sets the model ID for custom API providers when using `--auth-choice custom-api-key`.
- `--custom-api-key <key>`: (Non-interactive, optional) Sets the API key for custom providers. Falls back to `CUSTOM_API_KEY` environment variable if omitted.
- `--custom-provider-id <id>`: (Non-interactive, optional) Sets a custom provider ID.
- `--custom-compatibility <openai|anthropic>`: (Non-interactive, optional) Sets the compatibility mode for custom providers. Defaults to `openai`.
- `--gateway-port <port>`: Sets the Gateway port.
- `--gateway-bind <loopback|lan|tailnet|auto|custom>`: Sets the Gateway bind address.
- `--gateway-auth <token|password>`: Sets the Gateway authentication method.
- `--gateway-token <token>`: Sets the Gateway authentication token.

- `--gateway-password <password>`: Sets the Gateway authentication password.
- `--remote-url <url>`: Specifies the remote Gateway URL.
- `--remote-token <token>`: Provides a token for the remote Gateway.
- `--tailscale <off|serve|funnel>`: Configures Tailscale integration.

- `--install-daemon`: Installs the Gateway daemon.
- `--no-install-daemon` or `--skip-daemon`: Skips daemon installation.
- `--daemon-runtime <node|bun>`: Sets the runtime for the daemon. `bun` is not recommended for Gateway runtime.
- `--skip-channels`: Skips channel setup.
- `--skip-skills`: Skips skill setup.
- `--skip-health`: Skips health check setup.
- `--skip-ui`: Skips UI setup.

### Batch Pull Request Reviews with Codex

Source: https://github.com/openclaw/openclaw/blob/main/skills/coding-agent/SKILL.md

This section details how to perform batch pull request reviews in parallel using Codex. It involves fetching all PR refs, deploying multiple Codex instances (one per PR) in the background with PTY enabled, and then monitoring progress. Finally, results are posted to GitHub.

```bash
# Fetch all PR refs first
git fetch origin '+refs/pull/*/head:refs/remotes/origin/pr/*'

# Deploy the army - one Codex per PR (all with PTY!)
bash pty:true workdir:~/project background:true command:"codex exec 'Review PR #86. git diff origin/main...origin/pr/86'"
bash pty:true workdir:~/project background:true command:"codex exec 'Review PR #87. git diff origin/main...origin/pr/87'"

# Monitor all
process action:list

# Post results to GitHub
gh pr comment <PR#> --body "<review content>"
```

Sets up OpenClaw for development by cloning the repository, installing Node.js dependencies, and building the project. This is intended for contributors and developers who need to work with the source code. It also includes building UI assets.

```bash
git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install
pnpm build
pnpm ui:build
openclaw onboard

```

### Parallel Map (pmap) for Concurrent Transformation

Source: https://github.com/openclaw/openclaw/blob/main/extensions/open-prose/skills/prose/compiler.md

Introduces the 'pmap' operation in OpenProse, which performs transformations concurrently, similar to 'parallel for' but in pipeline syntax. It processes 'tasks' in parallel and aggregates the results.

```prose
let tasks = ["task1", "task2", "task3"]

let results = tasks | pmap:
  session "Process this task in parallel"
    context: item

session "Aggregate all results"
  context: results
```

### Openclaw Onboarding: Non-interactive Mode with Anthropic API Key

Source: https://github.com/openclaw/openclaw/blob/main/docs/reference/wizard.md

Automates Openclaw onboarding using a local mode and Anthropic API key for authentication. It configures the gateway port and bind address, and includes options to install and run the daemon.

```bash
openclaw onboard --non-interactive \
  --mode local \
  --auth-choice apiKey \
  --anthropic-api-key "$ANTHROPIC_API_KEY" \
  --gateway-port 18789 \
  --gateway-bind loopback \
  --install-daemon \
  --daemon-runtime node \
  --skip-skills
```

### Force Reinstall and Restart Gateway Service

Source: https://github.com/openclaw/openclaw/blob/main/docs/gateway/troubleshooting.md

If configuration checks do not resolve discrepancies between service configuration and runtime, these commands can be used to force a reinstallation of service metadata and restart the gateway. This is a more forceful step to reset the gateway's state.

```bash
openclaw gateway install --force
openclaw gateway restart
```

### Permissions Mapping

Source: https://github.com/openclaw/openclaw/blob/main/docs/nodes/location-command.md

Retrieves the location permissions map for a node, indicating the availability of location data reporting.

```APIDOC
## GET /nodes/{nodeId}/permissions/location

### Description
Retrieves the location permissions map for a node, indicating the availability of location data reporting.

### Method
GET

### Endpoint
`/nodes/{nodeId}/permissions/location`

### Parameters
#### Path Parameters
- **nodeId** (string) - Required - The unique identifier of the node.

### Response
#### Success Response (200)
- **location** (object) - An object detailing the location permission status. May be omitted if location is not supported or reported by the node.
  - **supported** (boolean) - Indicates if the node supports reporting location permissions.
  - **granted** (boolean) - Indicates if location permissions have been granted.

#### Response Example
```json
{
  "location": {
    "supported": true,
    "granted": true
  }
}
```

#### Error Responses
- **NODE_NOT_FOUND** - The specified node ID does not exist.
- **PERMISSION_DENIED** - The user does not have permission to access this information.
```

### Invoke Android Device/Personal Data Commands (CLI)

Source: https://github.com/openclaw/openclaw/blob/main/docs/nodes/index.md

Invokes various Android-specific commands to retrieve device status, information, permissions, notifications, contacts, calendar events, motion data, and app updates. Requires specific capabilities to be enabled on the node.

```bash
openclaw nodes invoke --node <idOrNameOrIp> --command device.status --params '{}'
openclaw nodes invoke --node <idOrNameOrIp> --command notifications.list --params '{}'
openclaw nodes invoke --node <idOrNameOrIp> --command photos.latest --params '{"limit":1}'
```

### SQL for Persistent Agent Memory Management

Source: https://github.com/openclaw/openclaw/blob/main/extensions/open-prose/skills/prose/state/postgres.md

These SQL commands manage the memory of persistent agents within OpenCLaw. They include reading the agent's current state, updating it, and recording specific agent segments with prompts and summaries.

```sql
-- Read your current state:
  psql "$OPENPROSE_POSTGRES_URL" -t -A -c "SELECT memory FROM openprose.agents WHERE name = 'captain' AND run_id = '20260116-143052-a7b3c9'"

-- Update when done:
  psql "$OPENPROSE_POSTGRES_URL" -c "UPDATE openprose.agents SET memory = '...', updated_at = NOW() WHERE name = 'captain' AND run_id = '20260116-143052-a7b3c9'"

-- Record this segment:
  psql "$OPENPROSE_POSTGRES_URL" -c "INSERT INTO openprose.agent_segments (agent_name, run_id, segment_number, prompt, summary) VALUES ('captain', '20260116-143052-a7b3c9', 3, '...', '...')"
```
