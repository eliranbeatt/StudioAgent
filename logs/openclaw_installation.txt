### Install OpenClaw with Local Node Runtime (Bash)

Source: https://github.com/openclaw/openclaw/blob/main/docs/install/installer.md

This script is designed for environments where a system-wide Node.js installation is not desired. It installs a local Node.js runtime within a specified prefix (defaulting to `~/.openclaw`), ensures Git is available, and then installs OpenClaw using npm under that prefix. This approach isolates the OpenClaw installation and its Node.js dependency.

```bash
#!/bin/bash

# Default prefix
PREFIX="${HOME}/.openclaw"

# Default Node.js version
NODE_VERSION="22.22.0"

# --- Install local Node runtime ---
NODE_DIR="${PREFIX}/tools/node-v${NODE_VERSION}"
NODE_TARBALL="node-v${NODE_VERSION}-linux-x64.tar.gz"
NODE_URL="https://nodejs.org/dist/v${NODE_VERSION}/${NODE_TARBALL}"

if [ ! -d "${NODE_DIR}" ]; then
  echo "Downloading Node.js ${NODE_VERSION}..."
  mkdir -p "${PREFIX}/tools"
  curl -fsSL "${NODE_URL}" -o "/tmp/${NODE_TARBALL}"
  tar -xzf "/tmp/${NODE_TARBALL}" -C "${PREFIX}/tools"
  mv "${PREFIX}/tools/node-v${NODE_VERSION}-linux-x64" "${NODE_DIR}"
  rm "/tmp/${NODE_TARBALL}"
  echo "Node.js installed to ${NODE_DIR}"
fi

# Add Node.js to PATH for this script
export PATH="${NODE_DIR}/bin:${PATH}"

# --- Ensure Git ---
if ! command -v git &> /dev/null; then
  echo "Git not found. Attempting to install..."
  if command -v apt-get &> /dev/null; then
    sudo apt-get update && sudo apt-get install -y git
  elif command -v dnf &> /dev/null; then
    sudo dnf install -y git
  elif command -v yum &> /dev/null; then
    sudo yum install -y git
  elif command -v brew &> /dev/null; then
    brew install git
  else
    echo "Could not automatically install Git. Please install it manually."
    exit 1
  fi
  echo "Git installed."
fi

# --- Install OpenClaw under prefix ---
echo "Installing OpenClaw to ${PREFIX} using npm..."
npm install -g openclaw --prefix "${PREFIX}"

# Create wrapper script
OPENCLAW_BIN_DIR="${PREFIX}/bin"
mkdir -p "${OPENCLAW_BIN_DIR}"

cat << EOF > "${OPENCLAW_BIN_DIR}/openclaw"
#!/bin/bash

# Find the npm-installed openclaw executable
OPENCLAW_EXEC="${PREFIX}/lib/node_modules/openclaw/bin/openclaw.js"

if [ -f "$OPENCLAW_EXEC" ]; then
  node "$OPENCLAW_EXEC" "$@"
else
  echo "Error: OpenClaw executable not found at $OPENCLAW_EXEC"
  exit 1
fi
EOF

chmod +x "${OPENCLAW_BIN_DIR}/openclaw"

echo "OpenClaw installed successfully to ${PREFIX}"
echo "Add ${OPENCLAW_BIN_DIR} to your PATH to use the 'openclaw' command globally."

```

## Runtime and Installation Options

### Bun Support
Bun is not recommended due to observed runtime bugs, particularly with WhatsApp and Telegram. Node.js is recommended for stable gateways. If experimenting with Bun, use it on a non-production gateway without WhatsApp or Telegram.

### Installation Methods

*   **Hackable (git) Install:**
    *   Provides a full source checkout, allowing for local builds and code/documentation patching.
    *   Best suited for contributors.

*   **npm install:**
    *   Installs the global CLI without the repository.
    *   Best for users who want to "just run it."
    *   Updates are managed via npm dist-tags.

### Documentation Links
*   [Getting started](/start/getting-started)

Source: https://github.com/openclaw/openclaw/blob/main/docs/platforms/oracle.md


### Install Dependencies and Build swabble (Bash)

Source: https://github.com/openclaw/openclaw/blob/main/Swabble/README.md

This snippet shows the basic commands to install necessary development dependencies using Homebrew, build the swabble project using Swift Package Manager, and then run setup commands for configuration and serving.

```bash
# Install deps
brew install swiftformat swiftlint

# Build
swift build

# Write default config (~/.config/swabble/config.json)
swift run swabble setup

# Run foreground daemon
swift run swabble serve

# Test your hook
swift run swabble test-hook "hello world"

# Transcribe a file to SRT
swift run swabble transcribe /path/to/audio.m4a --format srt --output out.srt
```

### Optimize Dockerfile for Faster Rebuilds with Layer Caching

Source: https://github.com/openclaw/openclaw/blob/main/docs/install/docker.md

This Dockerfile example demonstrates how to optimize rebuild times by strategically ordering commands to leverage Docker's layer caching. Dependencies are copied and installed before the rest of the application code, ensuring that `pnpm install` is only re-run when lockfiles or package metadata change.

```dockerfile
FROM node:22-bookworm

# Install Bun (required for build scripts)
RUN curl -fsSL https://bun.sh/install | bash
ENV PATH="/root/.bun/bin:${PATH}"

RUN corepack enable

WORKDIR /app

# Cache dependencies unless package metadata changes
COPY package.json pnpm-lock.yaml pnpm-workspace.yaml .npmrc ./
COPY ui/package.json ./ui/package.json
COPY scripts ./scripts

RUN pnpm install --frozen-lockfile

COPY . .
RUN pnpm build
RUN pnpm ui:install
RUN pnpm ui:build

ENV NODE_ENV=production

CMD ["node","dist/index.js"]
```

### Verify Installed Binaries in OpenClaw Gateway Container

Source: https://github.com/openclaw/openclaw/blob/main/docs/install/gcp.md

Executes commands within the running `openclaw-gateway` container to verify that the essential binaries (`gog`, `goplaces`, `wacli`) have been correctly installed and are accessible in the system's PATH. This confirms the success of the Docker image build process.

```bash
docker compose exec openclaw-gateway which gog
docker compose exec openclaw-gateway which goplaces
docker compose exec openclaw-gateway which wacli
```
