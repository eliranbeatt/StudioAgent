## Data model decisions (based on your schema)

* **Planned costs**: `materialLines`, `workLines` (you already have great fields and indexes)
* **Approved budget**: `projects.activeBudgetBaselineId` → `budgetBaselines.planned` (or baseline linked to `quoteVersionId`)
* **Margins**: `projects.defaults` (already exists: profitPct/overheadPct/riskPct)
* **Actuals**:

  * Today you have: `purchases` + thin `receipts`

**Add to `materialLines`:**

* `actualUnitCost?: number`
* `actualTotalCost?: number`
* `receiptItemIds?: Id<"receiptItems">[]`

**Add to `workLines`:**

* `actualTotalCost?: number`

**Add new tables (if not already added in your patch plan):**

* `receiptItems` (receiptId + extracted items + mapping to materialLine/workLine/task/element)
* (Optional later) `shareLinks` etc — not required for Accounting tab itself.

> If you want **Accounting P0 only**, you can ship without actuals and profit, but you explicitly asked for actual prices + profit, so I’m including them as P1.

## Priority and phased dev plan (1-day execution friendly)

### P0 — Must ship for “Accounting works”

**Goal:** Accounting tab shows correct totals, editable margins, sell price, line lists, delete row, and task links.

#### P0.1 Backend: Accounting snapshot query (single source)

Create a Convex query that returns everything Accounting needs in one call:

**`accounting.getSnapshot(projectId)`**
Returns:

* project defaults (risk/overhead/profit + excludeManagementLaborFromCost)
* planned totals:

  * materialsPlannedTotal
  * laborPlannedTotal (optionally exclude management)
  * plannedCostTotal
* computed margins:

  * riskAmount, overheadAmount, profitAmount
  * sellPriceTotal
* grouping:

  * perElement: { elementId, elementTitle, materialsTotal, laborTotal, costTotal, sellTotal, lines[] }
* raw lines:

  * `materialLines[]`, `workLines[]` including `taskId`, `elementId`, `sectionLabelHe`, `workType`, etc.
* baseline (if exists):

  * approvedCostTotals (materials/labor/total)
  * gaps = current − approved

**Implementation notes**

* Use existing indexes: `materialLines.by_project`, `workLines.by_project`, `elements.by_project`
* Keep computations inside query for consistency + speed.

#### P0.2 Backend: Update margins (editable on Accounting screen)

**`projects.updateMargins(projectId, {riskPct, overheadPct, profitPct})`**

* Patch `projects.defaults.*Pct`
* (Optional) also patch `updatedAt`

**Fast path (P0):** hard delete with confirm modal.

### P1 — “Actual prices + Profit” (next after P0)

**Goal:** track actuals per line from receipts/purchases and compute profit.

#### P1.1 Data: receipts expansion (you already have receipts/purchases)

Right now `receipts` is: `{ projectId, purchaseId?, fileId, createdAt }`
To support actuals:

* Extend `receipts` with optional: `vendorId`, `status`, `date`, `total`, `currency`, `extraction`, `fileIds[]`
* Add `receiptItems` table and connect to `materialLines/workLines`

#### P1.2 Backend: receipt workflow

* `receipts.create(projectId, fileId, purchaseId?, vendorId?)`
* `receipts.setStatus(receiptId, status)`
* `receiptItems.upsert(receiptId, items[])`
* `receiptItems.mapToLine(receiptItemId, { materialLineId? / workLineId? / taskId? / elementId? })`

#### P1.3 Backend: apply actuals to lines

Two options:

* **Manual mapping only (fast):** user maps receipt items to material lines; then:

  * patch `materialLines.actualTotalCost`
  * push `receiptItemId` to `materialLines.receiptItemIds`
* **Semi-auto (later):** match by vendor + itemName similarity.

Add computed fields in `accounting.getSnapshot`:

* actualMaterialsTotal, actualLaborTotal, actualCostTotal
* profit = sellPriceTotal − actualCostTotal
* variance vs planned = actual − planned

#### P1.4 UI changes

* Add “Actual” columns next to planned:

  * plannedTotalCost | actualTotalCost | variance
* Profit box in header:

  * Sell total, Actual total, Profit (number + %)

#### P1 Acceptance criteria

* Can attach receipt items and map to lines
* Actual totals appear on Accounting tab

## Key calculations (make them consistent everywhere)

Let:

* `materialsPlanned = sum(materialLines.plannedTotalCost ?? 0)`
* `laborPlanned = sum(workLines.plannedTotalCost ?? 0)`

  * if `excludeManagementLaborFromCost`, exclude `workLines.isManagement === true`
* `plannedCost = materialsPlanned + laborPlanned`

Margins:

* `risk = plannedCost * riskPct`
* `overhead = plannedCost * overheadPct`
* `profit = plannedCost * profitPct`
* `sellTotal = plannedCost + risk + overhead + profit`

Baseline (approved):

* source:

  * `project.activeBudgetBaselineId` → `budgetBaselines.planned` (you decide the planned shape; return totals)
    Gaps:
* `gapMaterials = materialsPlanned - approvedMaterials`
* `gapLabor = laborPlanned - approvedLabor`
* `gapTotal = plannedCost - approvedTotal`

Profit (P1):

* `actualCost = actualMaterials + actualLabor`
* `profitActual = sellTotal - actualCost`
