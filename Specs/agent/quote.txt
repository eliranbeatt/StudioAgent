# A1 - Quote Generator v2 (Dev Plan, adjusted to current repo)

## 1) Scope & Definition of Done

### Goal

Generate a client-ready Hebrew quote from the current cost snapshot (see Data Source decision), with:

- checkboxes to include/omit sections (elements, T&C, dates, agreements, options)
- customer-facing prices only (AFTER margins) - never expose internal vendor costs
- versioning + diff
- export PDF with logo + copy as text

### Definition of Done

1. Quote tab renders input fields + include toggles + "Generate quote (AI)".
2. Generates a new quote version stored in quoteVersions.
3. Quote output includes: scope, deliverables, schedule, price summary, assumptions, exclusions, terms, valid until.
4. Copy-as-text matches the quote content.
5. PDF export matches preview (typography/layout consistent, includes logo).
6. "Diff vs previous" shows meaningful changes (text + totals + included blocks).

Already present (no schema changes required):

- customerId? + denormalized customerName?

- rendered outputs:
  - quoteText_he (full quote)
  - quoteBlocks: structured blocks for UI (scope, deliverables, etc.)
  - pdfFileId?
- diff support:
  - contentHash (hash of normalized blocks + numbers)
  - previousQuoteId?

Compatibility note: keep totals with grandTotal so approveQuoteAsBaseline continues to work.
Why structured blocks? Because you need reliable diff + PDF rendering and consistent sections.

## 4) Pricing Logic - customer price only (critical rule)

### 4.1 Inputs for pricing (Decision already made in code)

Current behavior in convex/quotes.ts:

A) Primary: Accounting snapshot (financials.getAccountingView)
- Aggregates draft + committed accounting lines
- Pros: matches Accounting totals
- Cons: must explicitly avoid internal/vendor data in output

B) Fallback: Approved elementVersions
- Aggregates from elementVersions.snapshot when accounting is empty

### 4.2 Output required

For the quote, store and display SELL prices only:

- sellSubtotal = costSubtotal * (1 + risk + overhead + profit)
- Round rules (define once): e.g., round to nearest 10 NIS (optional)

Never store vendor names/costs inside the quote output blocks or PDF (unless explicitly requested).
Implementation note: you can store internal cost snapshot in DB for audit, but keep it in a hidden field and do not surface it in quote blocks/PDF.

## 7) Quote Agent v2 - prompt contract + schema (Hebrew output)

### 7.1 Inputs to agent (assembled server-side)

- project name, customer name, project description, specs
- included scope: elements list grouped as requested (by section/element)
- sellBreakdown: { groupName_he, includedItems_he[], sellSubtotalNIS }[]
- priceSummary: totals + VAT note rule
- schedule/dates if provided
- house rules: assumptions/exclusions/proof step/contingency/options language

### 7.2 Output schema (strict JSON, Hebrew values)

Return:

- title_he, intro_he
- scope_he[]
- deliverables_he[] (or grouped by element)
- schedule_he[]
- priceSummary_he (numbers included)
- options_he[] (each has name_he, deltaNIS, note_he)
- assumptions_he[]
- exclusions_he[]
- terms_he[]
- validUntil_he (human text)
- signatureBlock_he

Hard rule in system message: do not mention internal vendor costs or vendor names.

## 8) PDF Export (with logo) - implementation approach

### Option A (fastest & consistent): HTML + PDF

1. Create a single QuotePrintView React component that renders from quoteBlocks.
2. Server-side PDF generation using headless Chromium (Playwright) or a hosted HTML-to-PDF solution.
3. Store PDF in file storage and link via pdfFileId.

Pros: Typography parity with UI preview.
Cons: Slight infra complexity.

### Option B: Programmatic PDF (more deterministic)

Use a PDF library to render blocks (less CSS parity).
Pros: Deterministic.
Cons: More layout work.

Day-1 recommendation: Option A, since parity is important.
Status: Implemented using Playwright in convex/quotePdf.ts, with a simple HTML renderer and logo support.

---

## 9) "Diff vs previous" - what to diff (practical)

Compute diff across:

1. Numbers: total, subtotal, each sellBreakdown group total
2. Included blocks: which sections were included
3. Text blocks: assumptions/exclusions/terms/options (line-based diff)

Implementation:

- Store quoteBlocks as structured arrays and diff by key + normalized string
- For UI: show a Changed / Added / Removed list, plus number deltas
Status: Implemented in quotes.getDiff and Quote tab modal.

## 10) Testing & Acceptance (focused)

### Core tests

- Generate quote with:
  - elements by section
  - elements by element
  - include/exclude each checkbox block
- Verify no internal costs appear in quoteText_he or blocks.
- Verify totals:
  - sum(sellBreakdown subtotals) == priceSummary.subtotalBeforeVat
- PDF renders:
  - logo appears
  - Hebrew RTL alignment ok
  - same headings order as preview

### Edge cases

- No accounting lines yet - agent must output "missing info" questions instead of hallucinating
- Missing dates/specs - assumptions must include pending measurements/venue constraints notes
- Options included but none defined - output empty options section or suppress
