Here’s a catalog schema that will actually work for your studio long-term (wood + prints + hardware + paint + “weird one-offs”), while supporting:

Categories + types + variants (thickness/size/etc.)

Multiple units + conversions (sheet / m / m² / liter / kg / unit)

Multiple price sources (your manual, actual purchases, web search results)

Procurement logistics (online order / pickup / shipping / lead time / min order)

LLM flow: DB-first, web only for missing/stale, and every web hit gets saved

I’m describing it as Convex-style tables, but it’s generic DB design.

The big idea (the model that doesn’t break)
3 layers

Template (MaterialTemplate) = “what kind of thing is this?”
Example: “Plywood sheet”, “Print on PVC foamboard”, “Wood beam”

Variant / SKU (MaterialVariant) = “the exact spec you pick”
Example: “Plywood 17mm 1220×2440”, “PVC foamboard 5mm + matte lamination + CNC complex cut”

Price Record (PriceRecord) = “someone said this price at this time”
Sources: manual (your supplier memory), purchase (invoice), web (search result), quote (email/WhatsApp)

This separation is what lets you scale to “all all all” without chaos.

When a “pricing/web search” skill runs for items:

Try to resolve to templateId/variantId via synonyms + attributes

Query priceRecords:

same variantId

checkedAt within freshness window for that category

If found → no web search

If missing/stale → web search

Parse results into new priceRecords rows with sourceType="web"

Return price suggestions referencing the saved record IDs

const CatalogItemKind = v.union(
  v.literal("material"),        // wood, paint, screws…
  v.literal("print_service"),   // printing on substrate
  v.literal("cut_service"),     // CNC / laser / straight cut service
  v.literal("rental"),
  v.literal("shipping"),
  v.literal("other_service")
);

const UomCode = v.union(
  v.literal("ea"),
  v.literal("sheet"),     // IMPORTANT for wood boards
  v.literal("m"),
  v.literal("m2"),
  v.literal("sqm"),
  v.literal("m3"),
  v.literal("kg"),
  v.literal("l"),
  v.literal("set"),
  v.literal("box"),
  v.literal("roll"),
  v.literal("pack"),
  v.literal("job"),       // prints often end up “per job”
  v.literal("hour")
);

const PriceSourceType = v.union(
  v.literal("purchase"),
  v.literal("manual"),
  v.literal("web"),
  v.literal("quote"),
  v.literal("approvedElement")
);

const PricingModel = v.union(
  v.literal("per_unit"),
  v.literal("per_sheet"),
  v.literal("per_m"),
  v.literal("per_m2"),
  v.literal("per_pack"),
  v.literal("tiered"),
  v.literal("formula"),
  v.literal("unknown")
);

const Availability = v.union(
  v.literal("inStock"),
  v.literal("outOfStock"),
  v.literal("unknown")
);

const OrderMethod = v.union(
  v.literal("walkin"),
  v.literal("phone"),
  v.literal("whatsapp"),
  v.literal("website"),
  v.literal("email"),
  v.literal("unknown")
);

const CatalogAttributeDef = v.object({
  key: v.string(),            // e.g. "thicknessMm"
  labelHe: v.string(),        // e.g. "עובי"
  type: v.union(
    v.literal("number"),
    v.literal("enum"),
    v.literal("boolean"),
    v.literal("text")
  ),
  unit: v.optional(v.string()), // "mm" | "cm" | etc.
  required: v.optional(v.boolean()),
  enumOptions: v.optional(v.array(v.object({
    value: v.string(),
    labelHe: v.string()
  }))),
  commonValues: v.optional(v.array(v.any())), // quick chips in UI
});

1) Upgrade materialCatalog into a true “Template” table (non-breaking)

You keep existing fields, add these optional fields:

materialCatalog: defineTable({
  canonicalName: v.string(),
  unit: v.string(),
  synonyms: v.array(v.string()),
  typicalVendorId: v.optional(v.id("vendors")),
  tags: v.array(v.string()),
  active: v.boolean(),
  createdAt: v.number(),
  updatedAt: v.number(),

  // NEW (optional, backwards compatible)
  kind: v.optional(CatalogItemKind),
  categoryKey: v.optional(v.string()),         // "wood" | "prints" | "hardware" ...
  defaultUomCode: v.optional(UomCode),         // replaces free-text unit where possible
  attributeDefs: v.optional(v.array(CatalogAttributeDef)), // what parameters this item supports
  notesHe: v.optional(v.string()),
})
.index("by_name", ["canonicalName"])
.index("by_categoryKey", ["categoryKey"]);


Why this works: your UI can filter by categoryKey, and decide which controls to show using attributeDefs.

materialCatalogVariants: defineTable({

3) Replace “priceObservations-only” with a unified price evidence table

You can keep priceObservations for old flows, but for what you want (web results w/ URL + shipping), you need a richer table.

✅ NEW: catalogPriceRecords

catalogPriceRecords: defineTable({
  // Prefer variant-level pricing
  variantId: v.optional(v.id("materialCatalogVariants")),
  catalogId: v.optional(v.id("materialCatalog")), // fallback when variant unknown

  vendorId: v.optional(v.id("vendors")),

  sourceType: PriceSourceType,
  observedAt: v.number(),      // when we checked / found it
  currency: v.string(),        // "NIS"

  pricingModel: PricingModel,
  unitCost: v.optional(v.number()),   // for per_* models
  minQty: v.optional(v.number()),
  setupFee: v.optional(v.number()),   // prints
  notesHe: v.optional(v.string()),

  // Logistics snapshot (what your planner cares about)
  availability: v.optional(Availability),
  leadTimeDays: v.optional(v.number()),
  orderMethod: v.optional(OrderMethod),
  shippingAvailable: v.optional(v.boolean()),
  shippingCost: v.optional(v.number()),
  pickupAvailable: v.optional(v.boolean()),
  pickupAddressHe: v.optional(v.string()),

  // Evidence (MANDATORY for web)
  url: v.optional(v.string()),
  domain: v.optional(v.string()),
  title: v.optional(v.string()),
  rawSnippet: v.optional(v.string()),
  extractedFields: v.optional(v.any()),

  // Quality
  confidence: v.optional(v.number()), // 0..1
  createdBy: v.optional(v.union(v.literal("user"), v.literal("agent"))),

  // Link back to origin (receipt/purchase/search-run/etc.)
  sourceRef: v.optional(v.any()),

  // Dedup keys
  urlHash: v.optional(v.string()),
  offerFingerprint: v.optional(v.string()),

  createdAt: v.number(),
})
.index("by_variant_observedAt", ["variantId", "observedAt"])
.index("by_catalog_observedAt", ["catalogId", "observedAt"])
.index("by_urlHash", ["urlHash"]);

What this enables immediately

Your web-search skill saves each result as sourceType="web", with url, observedAt, shipping, etc.

Your pricing resolver does DB-first lookups with freshness rules.

5) Printing support (the part that usually breaks catalogs)

For printing, you have 2 common realities:

Some vendors give direct per-m² price + add-ons

Others give tiered / formula (min charge + setup + cut complexity)

If you want this clean, add OPTIONAL formulas:

pricingFormulas: defineTable({
  catalogId: v.id("materialCatalog"),  // usually a print_service template
  vendorId: v.optional(v.id("vendors")),
  formulaType: v.union(
    v.literal("print_m2"),
    v.literal("cnc_cut"),
    v.literal("custom")
  ),
  params: v.any(), // { basePerM2, minCharge, laminationAddPerM2, cncComplexAdd, ... }
  currency: v.string(),
  observedAt: v.number(),
  sourceType: PriceSourceType,
  url: v.optional(v.string()),
  notesHe: v.optional(v.string()),
  createdAt: v.number(),
})
.index("by_catalog_vendor", ["catalogId", "vendorId"]);


Then your print variants store attributes like:

substrate, thicknessMm, finish, lamination, cutMode, cncComplexity
…and pricing can be either a catalogPriceRecords row, or computed via pricingFormulas.

7) The DB-first rule you asked for (how queries should work)

Implement one resolver used by all skills + UI:

pricing.getBestPrice({ variantId, vendorId?, freshnessDays })

Priority:

catalogPriceRecords sourceType=purchase (newest)

sourceType=manual

sourceType=web within freshness

else “missing” → trigger web search → save results → return

That gives you exactly: look in table first, only search missing/stale.
